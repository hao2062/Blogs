# 01 系列导读与工程准备

## 简述
本篇为系列导读，目标是让读者在最短时间内搭建可复现的开发环境、理解系列目标与学习路径，并能快速得到第一个可验证的小成果（识别 sensor 并能读取基础信息）。

## 目标读者
- 嵌入式驱动开发者（有 Linux 基础，了解 I2C、Device Tree 及基本内核与驱动调试开发经验）
## 预期成果（系列阅读后主要收获）
- 理解视频流全链路及完整框架：从 sensor 电气特性/时序、DPHY/MIPI 到内核驱动与用户态处理。
- 掌握常见 camera 排查手段与工具：i2c-tools、media-ctl、v4l2-ctl、dmesg、trace 等。
- 能根据 datasheet 与参考驱动，从零移植新的 camera sensor：完成 Device Tree、驱动绑定、寄存器初始化与验证。
- 简要了解 ISP、视频编解码与 AI 应用，便于后续深入。

## 环境搭建步骤（概要）
1. 准备并连接硬件：按模块原理图接线，确保电源域、XCLK、RESET、MIPI lane 接好。
2. 烧写并启动目标镜像：将目标板刷入能访问串口/网络的镜像。
3. 在主机上准备交叉编译环境与内核源码（若需编译内核或模块）。
4. 安装并测试调试工具（见下）。

## 快速检查清单（上机后立即执行）
1. 串口输出：观察启动日志，确认内核加载与板级信息。

2. 检查 I2C/SC3336 连接：

```bash
# 在 Luckfox 平台上 I2C 总线号可能不同，示例：
i2cdetect -y 0
```

如果看见 sensor 的地址（以 SC3336 文档为准），说明 I2C 连通。

3. 查看内核日志（启动或插拔时）：

```bash
dmesg | grep -i -e mipi -e csi -e ov13850 -e camera
```

4. 查看 media graph 与 video 节点：

```bash
media-ctl -p
v4l2-ctl --list-devices
```

## 第一个可复现小成果（步骤细化）

目标：通过 I2C 检测并读取传感器 ID（以 SC3336 为例）

步骤：
1. 用串口登录目标板。
2. 在板上运行 `i2cdetect -y <bus>`（通常是 0 或 1），记录地址。

3. 使用 `i2cget` 读取 sensor ID 寄存器（参考 SC3336 datasheet，示例）：

```bash
i2cget -y <bus> <addr> <reg> w
```

(注：SC3336 的寄存器地址与访问方式以其 datasheet 为准，替换 `<reg>` 为厂商给定的 ID 寄存器地址）

验证：如果能读到合理的 sensor ID，表示 I2C 与 sensor 基本连通。
